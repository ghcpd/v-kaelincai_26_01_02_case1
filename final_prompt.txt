# Complete Bug Fix and Validation Task for Insurance Claim Calculator

## Role & Objective

You are a senior software engineer tasked with fixing a Python insurance claim calculator project that contains functional bugs, creating a corrected version in a new directory, and then executing a comprehensive validation to ensure all fixes are working correctly.

## Inputs & Context

**Source Project Location:** `issue_project/`
- Contains a buggy insurance claim calculator with known issues
- Includes comprehensive test suite and documentation
- 16 total tests with 5 currently failing

**Reference Documentation:** FIX_PROMPT.md and attachment requirements
- Business requirements and implementation specifications
- Bug descriptions and expected test outcomes
- Success criteria and deliverables

**Target Output Directory:** `issue_project_fixed/` (new sibling directory)

## Step-by-Step Instructions

### Phase 1: Analysis & Preparation
1. Read and understand `README.md` for business requirements
2. Review `KNOWN_ISSUE.md` to identify documented bugs
3. Examine `tests/test_claim_calculator.py` to understand expected behavior
4. Study `src/insurance_claim.py` to identify the buggy code
5. Run `pytest tests/ -q` to confirm which 5 tests are failing

### Phase 2: Create Fixed Project Structure
1. Create new directory: `issue_project_fixed/`
2. Create subdirectories: `src/` and `tests/`
3. Copy and create the following files with correct structure:
   - `src/__init__.py` (empty or minimal initialization)
   - `src/insurance_claim.py` (FIXED implementation - see below)
   - `tests/__init__.py` (empty or minimal initialization)
   - `tests/test_claim_calculator.py` (copy unchanged from original)
   - `requirements.txt` (copy from original)

### Phase 3: Fix All Bugs
Identify and fix the following bugs in `insurance_claim.py`:

**Bug 1: Deductible Boundary Condition**
- Location: `get_deductible()` or equivalent function
- Issue: Incorrect comparison operator (< instead of <=) at 2000 threshold
- Fix: Change condition from `if loss_amount < 2000:` to `if loss_amount <= 2000:`
- Impact: Fixes loss amount exactly 2000 handling

**Bug 2: Missing Driving Years Bonus Application**
- Location: `calculate_payout()` function
- Issue: `_apply_driving_bonus()` method exists but is never called
- Fix: Apply driving bonus to payout calculation with correct integration
- Impact: Applies 5%, 10%, or 15% bonus based on driving years (3, 5, 10+ years)

**Verification:**
- Maintain identical public API (class and method names)
- Do NOT modify test cases
- All 16 tests must pass after fixes
- Keep the same code style and structure
